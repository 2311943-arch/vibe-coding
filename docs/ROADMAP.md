# 개발 로드맵 (5단계)

PRD v0.2의 개발 단계(Phase 0~4)를 그대로 1~5단계로 번호를 다시 매겼습니다.
앞 단계가 끝나기 전에는 뒤 단계에 큰 비용을 쓰지 않습니다(PRD 12장).

| 단계 | PRD | 목표 | 주요 산출물 | 완료 기준 |
|---|---|---|---|---|
| 1단계 | Phase 0 | 기술 타당성 검증 | `analysis/` 평가 하니스, 샘플 매니페스트, 기준선 리포트 | 권한이 확인된 샘플 10개 이상에서 지표 측정, 모델·파이프라인 선정 또는 지원 범위 축소 결정 |
| 2단계 | Phase 1 | 악보 데이터 엔진 | 음표·코드 스키마 확정, 줄·프렛 변환(`MIDI → 타브`), 타브 렌더링 | 테스트 데이터에서 변환 결과가 물리적으로 연주 가능 |
| 3단계 | Phase 2 | 분석 백엔드 | FastAPI 작업 API, Celery/Redis 큐, FFmpeg 전처리, 모델 파이프라인, 만료 처리 | 오디오 입력부터 결과 저장까지 비동기로 동작 |
| 4단계 | Phase 3 | 웹 UI | Nuxt 3개 화면(링크 입력·분석 진행·악보 결과), 오류·부분 결과 상태 | 3개 화면이 실제 API 계약으로 동작 |
| 5단계 | Phase 4 | 통합·사용자 테스트 | 종단 간 테스트, 모바일 확인, 실패·재시도 테스트, 사용성 평가 | 사용자 5명 이상 평가 완료 |

## 현재 상태

- **1단계: 코드 완료, 실측 대기.** 평가 하니스와 기준선 코드 구현. 실제 샘플 오디오와 외부 전사 모델
  (Basic Pitch, Demucs)이 아직 없어 실측은 못 했습니다. 자세한 내용은 `analysis/README.md`.
- **2단계: 구현 완료(`engine/`).** Pydantic 스키마(TS 계약과 일치 테스트 포함), MIDI → 줄·프렛 변환(DP로 손 이동 최소화,
  못 옮기는 음표는 이유와 함께 반환), ASCII 타브 렌더러. 변환 품질은 합성 화음으로만 확인했고, 실제 전사 결과로는
  1단계 샘플이 생긴 뒤 확인해야 합니다. 웹용 SVG 타브 렌더링은 4단계에서 만듭니다.
- **Apify 연동(3단계 선행분):** `server/utils/apify.ts`가 공개 릴스의 영상 주소를 확인하고 작업 흐름에 연결됩니다.
  기본은 꺼져 있고(`NUXT_APIFY_TOKEN` 비어 있음), 실제 호출은 아직 해 보지 못했습니다. 영상 내려받기는 3단계에서 합니다.
- **4단계(웹 UI) 선행분:** Nuxt 4 골격, PRD API 계약을 따르는 데모 서버 라우트(`server/api/analyses`), 공유 타입·유틸
  (`shared/`)까지만 먼저 만들어 두었습니다. 화면 3개는 만들지 않았습니다.

## 단계 사이의 결정 사항

- 1단계 끝에서 정할 것: 전사 모델 선택, 보컬/반주 분리 사용 여부, 지원 영상 범위, 성공 지표 목표치(기준선 측정 후).
- 3단계 시작 전에 정할 것: 업로드 대체 경로를 MVP에 포함할지.
